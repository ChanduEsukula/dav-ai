# Current pharmaceutical explorer architecture

React/Vite renders one search screen, exact-product selection, recall and adverse-event panels, provenance, and a native accessible PDF dialog. Search and selected product IDs survive refresh/back in the URL. Abort signals prevent stale results replacing a later selection. Report identifiers live in uncontrolled dialog fields, are submitted only by POST, and clear on close/download. No local storage, analytics, auth, OCR or external model is used.

FastAPI mounts only drug catalog, stored safety, shared evidence/coverage and report routers. Existing opaque product IDs, consumer eligibility, label admission, matching/applicability and source boundaries remain authoritative. Ingredient search joins sealed ingredient membership so combination products remain discoverable. Monthly AE rows are read directly from `ae_monthly`; absent months are not filled with zeroes. No ingredient counts are combined into a product total.

`connect_release` denies deployed environments before opening the artifact. In local mode it opens SQLite `mode=ro`, enables query-only access, checks required tables, schema version, manifest identity/policy, and the sealed release SHA-256. Checksum caching uses path, size, mtime and ctime and detects changes during hashing. Repository reads close their connections. `/health` remains independent; `/ready` uses the same connection gate as all data/PDF reads. The original external artifact verifier and its evidence receipts remain intact.

`drug_evidence` projects the same repository drug identity, linked recalls, component AE summaries/reactions/months, and public source dates/URLs for both the UI and the report. Raw manifest archive paths are not exposed as source-vintage metadata. Compatible safety/label/timeline APIs remain available with the P0-1 consumer-admission fix. Label storage/normalization and matching code remain available for rebuilds.

PDF generation adapts the existing `report_pdf.py` ReportLab/BytesIO infrastructure into a paginated document with repeated table headers and source citations. All user and evidence text is escaped before entering paragraphs. No HTML template, executable formula, remote fetch, arbitrary path or permanent report file is accepted. Fixed attachment names contain no personal identifiers. Bounds are enforced before rendering; failures release concurrency slots in `finally`. Client rate records hold only network addresses and monotonic timestamps, capped at 4096 clients and pruned after a minute. Report response errors also carry no-store headers. Request logs contain paths/status/durations, not bodies; the supplied runtime command disables server access logging.

Python runtime packaging excludes PostgreSQL, HTTP clients, research libraries, test runners and build parsers. Offline code and its dependencies remain in the repository for rebuilding/auditing the evidence. Original PostgreSQL migration chains and experimental datasets are historical offline material. Prior architecture/progress documents describe superseded features and are retained as historical records; this document defines the current application.

The production image is intentionally unable to serve the unapproved artifact. Before any deployment, separately review publication authorization, ingredient cohort/coverage limitations, accessibility, ingress rate/body/time limits, reverse-proxy logging, operational monitoring, dependency/image patching and frozen-artifact mount permissions. No automatic activation, new production database or public publication has been implemented.


Post-simplification hardening adds an outer ASGI report boundary covering redirects and errors, bounded/timed body reads, non-reflecting validation errors, bounded in-memory PDF output, safer report failure handling and constrained CORS. The artifact gate checks device/inode as well as file timestamps, verifies before opening and serializes cold checks. Runtime dependencies are hash-locked and image bases digest-pinned. Offline candidate selection/rollback is a rehearsal only; the deployed denial guard remains. Required release integration is separate from artifact-independent CI and cannot succeed via skipped critical checks. See docs/hardening/ARTIFACT_OPERATIONS.md for operating instructions and approval requirements.


Managed artifact installation is specified in docs/staging-artifacts/OPERATIONS.md. The operator copies/reverifies immutable version directories and atomically selects one; the read-only runtime pins that selection until restart and performs strict startup validation. Publication denial in staging/production is unchanged. The private Compose architecture exposes no ports and is configuration/build-only while authorization remains blocked.
